# Supabase 反向代理（中国大陆网络用）

## 这个目录是干什么的

PUSHUP 的云端数据放在 Supabase。Supabase 的 API 域名是 `xxxx.supabase.co`，**这个域名在中国大陆的网络里经常被 TLS 阻断**——表现就是所有请求都报 `Failed to fetch`，App 里登录不了、同步不了、动态刷不出来。

数据库和项目本身没坏。实测证据：

| 测试 | 结果 |
|---|---|
| 从境外出口访问 `https://zqrlolyntlcewrwfhumd.supabase.co/rest/v1/` | 正常返回 `{"message":"No API key found in request"}` |
| 从国内网络直连同一地址 | DNS 能解析，TCP 能连上，但 **TLS 握手阶段被重置** |
| 同一时刻访问 `supabase.com` | 正常 200 |

所以解决办法不是改配置，而是在中间加一层**国内能访问到的转发服务**：

```
手机 / App  ──https──▶  云函数（国内域名）  ──https──▶  supabase.co
             通畅                    出境，能通
```

这个目录里就是那一层。两条代码都能直接用：

| 文件 | 平台 | 说明 |
|---|---|---|
| `scf/index.js` | 腾讯云云函数 SCF | **推荐**，函数 URL 直接给域名，免备案、免买域名、免配 API 网关 |
| `fc/index.js` | 阿里云函数计算 FC 3.0 | 备选，`*.fcapp.run` 默认域名官方声明"仅限测试" |

两个文件都**没有任何 npm 依赖**，只用 Node 内置模块，可以直接在网页控制台里粘贴保存。

功能上它们做四件事：

1. 把路径、查询串、请求方法、请求体原样转发给 Supabase
2. 透传 `apikey` / `Authorization` / `Prefer` / `Content-Type` 等关键头
3. 补齐 CORS（含 `OPTIONS` 预检），否则 WebView 里会被跨域拦掉
4. 只放行 `/rest/v1`、`/auth/v1`、`/storage/v1`、`/realtime/v1`，不做任意网站的公开代理

## 一、腾讯云云函数 SCF（推荐）

### 0. 准备

- 注册腾讯云并完成实名认证
- 控制台搜索「云函数」进入 SCF，首次使用按提示开通（免费）

### 1. 新建函数

云函数控制台 → **函数服务** → **新建**

| 项 | 填什么 |
|---|---|
| 创建方式 | 从头开始 |
| 函数名称 | `pushup-proxy` |
| 运行环境 | **Node.js 16** 或 **Node.js 18**（都可以） |
| 地域 | 广州 / 上海 / 北京（离你近的） |
| 函数代码 | 选「在线编辑」，把默认内容**全删掉**，粘贴 `scf/index.js` 全文 |
| 执行方法 | `index.main` |
| 内存 | 128 MB 就够 |
| 超时时间 | **20 秒**（默认 3 秒会被截断，务必改） |
| 网络 | 默认（**不要选 VPC**，选了又没有 NAT 网关就出不了外网） |

保存并部署。部署完可以在控制台点「测试」，事件模板随便选一个，只要不报语法错误就说明代码运行起来了（真实的转发测试看第 3 步）。

### 2. 开一个「函数 URL」

函数详情 → **函数 URL**（有的版本在「触发器」页里，叫「添加触发器 → 函数 URL」）

| 项 | 必须选 |
|---|---|
| 是否启用 | 是 |
| **集成方式** | **响应集成** ← 选错的话返回的是一坨原始 JSON 字符串，前端用不了 |
| **认证方式** | **开放 / 免认证** ← 选 CAM 会要求签名，App 请求会 401 |

创建后拿到一个地址，形如：

```
https://abc1234567-xxxxxxxx.scf.tencentcs.com
```

> 只复制到域名结尾，**不要带任何路径**。

### 3. 验证（30 秒）

用手机浏览器（**先关掉代理 / VPN，用你平时那个网络**）打开：

```
https://你的函数域名/rest/v1/
```

- 看到 `{"message":"No API key found in request","hint":"..."}`
  → **成功**。这说明这条路已经通了，剩下就是把地址填进 App。
- 看到 `{"message":"此代理只转发 Supabase 接口"}`
  → 也说明通了，只是你访问的路径不在白名单里（正常现象）。
- 看到 `代理连不上 Supabase：...`
  → 函数能跑，但它出不了外网。检查：是不是把函数放进了 VPC、或地域网络有问题。
- 看到 401 / 403 / CAM 签名相关
  → 函数 URL 的认证方式没选「开放」。
- 一直转圈 / 打不开
  → 函数 URL 没启用，或域名抄错了（多了路径、少了字母）。

PC 上也可以用命令验证（能直接看到转发后的真实响应）：

```bash
curl -i "https://你的函数域名/rest/v1/" \
  -H "apikey: sb_publishable_O7AmNzcRHCKtWThXB9_8tg_xWaMoRQU"
```

### 4. 填进 App

**App（v1.9 起）**：我的 → 设置 → **服务器地址** → 粘贴函数域名 → 先点「测一下这个地址」→ 再点「保存并重启」。
设置页那一行会从「官方直连」变成「代理 · 你的域名」，想退回随时点「恢复官方」。

**管理台**：连接设置 → Project URL 填同一个函数域名 → 「保存并连接」→ 再点「连接自检」。
自检里 8 张表应该全部变成 ✓（`service_role` 未填时是只读模式，这是正常的）。

## 二、阿里云函数计算 FC 3.0（备选）

1. 函数计算控制台 → 创建函数 → **事件函数**
2. 运行环境 Node.js 18，**请求处理程序**填 `index.handler`
3. 代码里粘贴 `fc/index.js`
4. 函数配置：内存 128MB、**超时 20 秒**、不要挂 VPC
5. 触发器 → 创建触发器 → **HTTP 触发器** → 认证方式选「无需认证」→ 拿到 `https://xxx.cn-shanghai.fcapp.run` 地址
6. 验证方法与上面一致

> 阿里云官方文档明确写了 `*.fcapp.run` 默认域名**只能用于测试环境**，长期用建议绑自定义域名。所以这个方案放在备选。

- 调用次数：**100 万次**
- 资源用量：**40 万 GB-秒**

按 10 个人、每人每天开 App 20 分钟算，一个月大约 1~10 万次调用、几万 GB-秒，**在免费额度内，实际花费 0 元**。

## 四、为什么不能更省事

- **买域名 + Cloudflare Worker**：能用，但要域名年费，且 Cloudflare 的 IP 在国内部分网络也会被干扰。
- **给手机装代理 / 加速器**：零改动，但每个用的人都得装，网络一抖就断。
- **把 Supabase 换掉**：登录、8 张表、行级权限、实时同步全要重写，成本最高。

反代的好处是：数据库、表结构、数据、App 逻辑**全都不用动**，只是把「访问地址」换了一层。以后如果代理域名变了，App 里改一下地址就行，不用重装。

## 五、注意点

1. **6MB 上限**：云函数的请求体和响应体都有上限（约 6MB）。App 里动态图片是 base64 存库的，所以 v1.9 把一次拉取的条数收小了（动态 40 条、私聊 150 条）。图片多的账号如果还遇到列表加载失败，再往下调条数即可。
2. **函数 URL 是公网可访问的**：别人知道了也能调你的代理。代码里已经限制了只能访问 Supabase 的四个接口，且 `apikey` 本身就是客户端公开值（真正的权限由 Supabase 的行级权限控制），所以风险可控。如果你介意，可以在腾讯云给函数 URL 加 IP 限流。
3. **别把 `service_role` 写进任何仓库或前端**：它是数据库管理员权限。管理台里那个输入框只存在你自己手机的本机存储里。
4. **更新检查**：App 的版本检查走 `api.github.com`。如果那台手机连 GitHub 也不通，就收不到更新提示——那就以我直接发你的 APK 为准。
5. 改了 `scf/index.js` 里的 `UPSTREAM`（比如以后换了 Supabase 项目）要重新部署一次。
